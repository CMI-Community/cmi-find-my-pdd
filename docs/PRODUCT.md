# PDD404 v0.2.0 产品与架构合同

规格日期：2026-10-06（曼谷）。本合同落实用户确认的单号查询原型，替换 v0.1.0 的图片识别主流程与管理员专属联系人模型。代码、测试和运行手册按本合同执行。

## 产品与范围

PDD404（pdd404.app）是 CMI Community 的公益包裹互助项目和社区展示入口。普通用户没有注册、登录或数据库直接访问。国内快递单号可手动输入，或由当前设备的摄像头解码条形码；扫码画面不上传。首发不依赖付费 OCR，不自动发送微信或短信通知。

复用现有 React/TypeScript/Vite 开源客户端、Supabase Edge API、管理员 Auth、社区配置、管理凭证与加密备份。Vercel 使用独立 PDD404 项目。因 Supabase 免费活跃项目限额，用户于 2026-10-06 授权将独立测试项目 fogncjjsnakbhfdbfvdi 转为生产，不再保留该云端测试库；后续测试使用隔离本机 PostgreSQL，预览不得接入生产登记。不得部署至旧 Swap 项目或复用其数据库。

## 用户流程

首页默认“我丢件了”，另有“我多收件了”；国内快递单号输入框、扫码和查询始终可见。按白底、深色正文和淡紫操作色实现已确认原型，正文至少16px、触控区域至少44px，状态有文字而不只靠颜色。

点击查询并到达服务器时记日志。对侧存在有效登记优先返回匹配；否则同侧已登记返回重复；两侧都没有有效登记则进入本机待提交列表。已交还显示已结案，撤回登记退出匹配。服务失败、配置不全和限流不得写成未找到。

匹配弹窗立即显示对侧填写的微信或电话、登记时间及复制按钮，不增加管理员协调或双方批准步骤。提示“找到相同国内单号的登记，请核对包裹后安排交还”，不能声称已确认所有权。查询者可选在同一弹窗留下自己的联系方式，不填写也能联系对方。

两种模式分别保留本机待提交列表，切换或刷新不丢内容；可逐行移除、按规范单号去重。微信或电话填写一次后点击“确认挂失”或“全部提交”。服务器事务内逐条重查，返回登记、重复、新匹配或失败。成功项进入回执，失败项保留，网络重试不产生重复登记。只有服务器确认后才写“已登记”；未提交列表只是本机暂存。

提交成功提供保存回执及本人管理链接。后续再次查询或打开管理链接查看新匹配；不能承诺站外通知。公众号、群二维码和小助手来自实际配置，缺项显示不可用，不能造二维码、联系资料或统计。

## 扫码与联系方式

点击扫码立即申请摄像头权限，允许后优先启动后置摄像头，本机ZXing解码一维条码。首次有效解码即停止媒体轨道、关闭取景层并填号；用户核对后手动查询。关闭、切换模式、页面隐藏、卸载及迟到授权均正确停止摄像头。拒绝权限、没有相机或占用时解释原因并保留手动输入。

相机预览保持真实画面比例；前置或桌面相机默认使用镜像预览，后置保持正常，可手动切换显示方向。镜像仅影响预览，不改变解码输入。允许权限后存在多台相机时可切换，先关闭旧相机。保留设备默认对焦设置，只在设备报告支持时提供自动或手动对焦；操作失败说明原因，不中断原扫描。不支持网页调焦时提示将条码移远至清楚，或使用手机扫码，不宣称已解决物理镜头限制。

联系方式为 `{kind: 'wechat' | 'phone', value: string}`。表单明确说明“联系方式用于包裹对接，会展示给查询相同完整单号的对方”。只使用本人填写的联系资料，不能从旧图片中推断。

专用完整单号POST查询响应明确允许对侧联系资料。普通公开记录、分享页面、公开编号、尾号、查询参数开关不得取得联系人；管理凭证、原图、地址及管理员能力不随匹配返回。此规则是用户确认的v0.2.0变更，不沿用旧的“联系方式仅管理员可见”限制。

## 数据与一致性

- `pdd_waybills`：规范国内单号唯一，每个单号一条主记录，含稳定公开编号、处理状态、版本及更新时间。
- `pdd_registrations`：主记录下的丢件/多收件登记，含联系方式、时间、来源与管理凭证摘要；每侧最多一条有效登记。重复不覆盖原联系人、不给原登记管理权限。可选匹配联系提交在该侧尚无登记时创建登记；已存在时只追加联系历史。
- `pdd_query_events`：查询UUID、规范单号、模式、服务器`timestamptz`、结果及可选联系历史，尚无正式记录的查询也记日志。网络重放同UUID不重复日志，新的用户查询产生新UUID。界面使用Asia/Bangkok显示时间。

号码只去空白、统一英文字母大小写，保留前导零，不替换0/O或1/I。只按完整国内单号精确对应，不以尾号、订单号、集运总单或模糊线索匹配。手动/条码来源不伪装成OCR证据。

唯一约束、事务锁、版本与幂等键覆盖查询至提交的竞争窗口、并发登记和断网重试。业务表开启RLS，匿名及普通认证用户无直接权限；事务RPC仅service_role调用。管理凭证至少32随机字节、服务端仅存摘要、请求头传递，管理URL放fragment；公开分享不带凭证。

## 管理与生命周期

管理员按一个单号聚合双方登记、全部查询时间、联系补充与处理历史，支持核实、确认归属、实际交还、撤回和异常记录。全部更改写审计，确认归属不等于实际交还；只有实际交还幂等增加找回数。

查询日志30天清理。正式联系方式活跃期间保留，结案或撤回30天后清理；保留匿名交还事实。清理定时任务不依赖OpenAI。每日加密备份滚动7份，包含新表、Auth和社区素材，真实恢复至隔离环境验证；备份、凭证、真实资料不入Git。

旧图片模块保留但不挂载OCR草稿自动处理器，首发关闭旧写入口。已有旧公开/管理读接口仍脱敏兼容。核心health/readiness不要求OpenAI或worker识别配置。

## 验收与发布

必须通过npm run check、npm run build，虚构单号双向查询、对侧优先、重复不覆盖、提交时新匹配、批量部分失败、幂等、无凭证不可修改、RLS拒绝、联系方式专用白名单、实际交还只计一次与清理测试。新迁移完成真实PostgreSQL事务/并发和隔离恢复。

真实iPhone Safari、微信浏览器和桌面走通扫码及拒绝权限、相机关闭、360px页面、刷新和网络失败。生产域名DNS与HTTPS有效、前后端版本一致、管理员及备份可用之后开放登记。通过codex分支、PR、CI合入main；只在生产验收后创建运行标签。真实部署状态写入docs/releases/；首发故障关闭登记、保留已接收资料和真实联系入口。
