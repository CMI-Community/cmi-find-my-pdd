# 版本界面快照

维护者要求：每次界面修改前留存当前版本的全部用例状态；每次发布前留存当前版和候选版，能够回看每个版本实际的界面。自动应用，无须再次征求保存本地快照的确认。此 skill 不授权部署、发送消息或修改生产资料。

## 触发与时序

- 接到界面改动时，在第一次修改 UI 源码前完成 **baseline**。不要等改完才拍，也不要拿新页面冒充旧版本。
- 发布运行版本前，确认 baseline 对应当前线上运行版本，完成 **candidate**；部署经授权且验收通过后保存 **production**。前端和 API 的 SHA 可以不同，分别记录。文档合并的 HEAD 不能冒充正在运行的 SHA。
- 同一次修改与发布可以复用已封存且身份、矩阵、截图哈希均一致的 baseline。当前版本变化则重拍。后续修复属于新候选包，不能覆盖上次图。
- 仅文档或 skill 修改且不改变运行界面时，记录工作流变动，不捏造一次应用发布。历史截图只按原证据整理；缺失的历史状态标明缺口。本地重建旧 SHA 要标为“历史重建”，不能当时拍摄的生产证据。

## 固定保存位置与版本身份

默认根目录为项目根目录的 `output/playwright/releases/`。PDD404 的固定绝对位置：

`/Users/guanchao/Documents/ChatGPT/CMI SWAP/output/playwright/releases/`

每包使用 `<曼谷时间>-<version>-<frontendSha前12位>-<phase>-<唯一后缀>/`，不覆盖旧包。包内至少有：

- `manifest.json`：版本标签、实际前端和 API SHA、阶段、来源 origin、曼谷和 UTC 时间、冻结清单哈希、完成状态、图片 SHA256。
- `cases.json`：此次版本全部适用 UI 用例和视口。
- `coverage.json`：每个状态 × 视口的截图、实际观察、数据来源和覆盖结果。
- `images/`：PNG 截图；长页面另有全页图，长弹窗另有滚动末尾图，原生确认框保留实际系统表面截图。
- `index.html`：离线可浏览图集，显示状态、来源及未完成项。

版本号沿用真实标签；没有版本号时用 `unversioned-<sha前12位>`。核对部署记录、平台来源或构建资源以确定当前运行代码。记录构建环境、功能开关、浏览器版本和 mock 方法，避免同 SHA 不同配置被当作同一个界面。输出只保存安全元数据；不保存凭证、原始响应、私密浏览器 profile、完整含参数 URL 或生产个人资料。快照是本机历史档案，不能承诺已有异机备份。保留 `output/` 的 Git 忽略规则。

## 全状态覆盖

“全部用例”指该版本所有不同的用户可见状态，不是仅首页，也不是每个相同布局的输入值都重拍。

PDD404：先读 [状态矩阵说明](references/pdd404-cases.md)，以 [可执行清单](references/pdd404-cases.json) 为起点核对 `docs/PRODUCT.md`、`docs/ACCEPTANCE.md` 和实际路由/状态分支。别的应用从它自己的路由、规格、弹窗、状态机和可见错误推导清单，沿用同一 JSON 格式。

覆盖内容至少包括正常、空、加载、校验错误、服务错误、成功、禁用、权限缺失、状态转换，以及实际适用的各模式/查询方式。PDD404 还必须包括四个首页及队列组合、完整单号/姓名/疑似结果、登记和回执、本机记录、公开分享、两种私密管理、相机/扫码、反馈、后台各页及监控。新增 UI 分支要扩展清单，删除或未发布的功能需写明依据。

主要页必须拍 320×844、390×844、1280×900；每个其他可见状态至少 390×844 和 1280×900。窄屏特有、focus/hover、减少动态效果、素材失败和长内容按实际分支补充。路由别名验证跳转结果即可。基线清单冻结后，不得删条目来获得完成状态。

每项只能是：

- `captured`：实际浏览器截图存在，观察说明与画面吻合。
- `not_applicable`：这个版本确实没有此状态，给出具体代码/规格/开关依据。不可用来跳过难拍、超时或权限失败。
- `pending` / `blocked`：尚未完成，保留具体原因。

baseline 或 candidate 有 pending/blocked，或无法确认当前版身份时，先完成不依赖该缺口的工作，再明确报告；不得继续依赖它的 UI 改动/发布，也不得称全状态归档完成。这是维护者本次明确提出的先拍后改要求。不要自行放宽为首页截图。

## 实际拍摄

优先复用项目现有浏览器自动化；有终端 Playwright 时按其本机技能操作。没有固定工具时选可用的真实浏览器控制工具。此 skill 的归档 helper **不会拍图**，完整图集不能仅靠运行 helper 获得。

1. 使用与目标 SHA 相同的生产构建，在隔离浏览器存储中拍摄；只改变测试输入/网络响应，不替换 JSX/CSS 或用图片生成器制作界面。基线应在干净的临时 checkout 重建，保留用户未提交改动。
2. PDD404 全状态用独立本机 API 或浏览器网络截获的合成 DTO。按照合同做真实操作和状态转换，不在生产创建登记、查询日志、反馈、管理动作或重置邮件来拍图。阻断生产 API、Auth、业务 Storage 与埋点出站；品牌图可用已授权本地资产。真实线上只读公开页可以补拍，必须标为 `public-readonly`。生产配置缺项就拍缺项，不能用 mock 改写线上画面。
3. 正常截图等待对应语义状态、字体和图片就绪，再观察视口溢出；加载/禁用状态通过受控响应停留拍摄，不以任意等待猜进度。固定合成时间和样本，记录数据来源。浏览器错误和预期模拟失败分开记录。
4. 普通网页截图设置 deviceScaleFactor=1，先拍实际视口；页面超出视口时再拍 full-page。长弹窗/相机控件要拍顶部和内部滚动末尾，覆盖主要操作按钮。原生确认框、浏览器表单校验等用能够捕获原生表面的系统/浏览器工具，清单标 `captureType: native-surface`；保留原图真实像素，不能代造 HTML 提示或为了尺寸匹配拉伸。相机替身、mock 认证和合成结果只证明界面状态，不能宣称真机扫码、登录或业务接口已验收。
5. 查看所有图及索引，核对页面、标题、状态和数据源；至少重点查看每种独立布局与所有异常状态。不能把未进入目标状态的截图挂到该状态上。保存无私密输入内容的浏览器/配置说明。

凭证可以只在隔离测试内存中使用；图片不得含真实姓名、微信、电话、完整单号、备注、管理员资料或管理 URL/fragment。采用明确的 `PDD404TEST...`、合成人名和联系样本，并标记 synthetic。公开页不应出现合同禁止的字段；发现泄露先报告并修复，不把它当正常截图。不要为了隐私裁切界面主控件；优先用合成数据重拍。

## 归档 helper

先冻结矩阵，初始化唯一目录：

```sh
python3 <skill目录>/scripts/archive.py init \
  --root '<项目根>/output/playwright/releases' \
  --version '<真实版本或 unversioned-sha>' \
  --frontend-sha '<实际前端40位SHA>' \
  --backend-sha '<实际API40位SHA或unknown>' \
  --phase baseline \
  --source 'http://127.0.0.1:5187' \
  --cases '<skill目录>/references/pdd404-cases.json'
```

把实际截图放进 `images/`，填写生成的 coverage 行。`image` 为视口图，`fullPageImage` 为需要的全页图；路径相对于包目录，`observed` 写真实观察和浏览器/构建配置摘要，`dataSource` 为 `synthetic` 或 `public-readonly`。原生表面图不要求像素等于 CSS 视口，helper 记录真实尺寸；`observed` 必须包含 `os=...; browser=...; cssViewport=390x844; dpr=2; bounds=...` 和观察，写明系统、浏览器、目标视口、DPR 和截图范围。原生状态确实不适用于该版本时，`reason` 和 `observed` 都要写具体依据；工具不支持捕获仍是 blocked。有更多末尾/交互图则加入矩阵独立行。把未包含在冻结矩阵中的新增状态放入新的归档包，不能改动已封存包。

```sh
python3 <skill目录>/scripts/archive.py finalize '<归档包绝对路径>'
```

只有截图实际存在、尺寸正确、清单无漏项、所有项 captured/有依据的不适用，helper 才返回 0 并封存。未完成返回非零并显示缺口；不要把退出失败忽略成已完成。它检查文件、覆盖和哈希，无法证明截图来自正确页面，人工/agent 的画面观察仍必需。已封存包再次校验会检测文件篡改，不允许原位重拍。

## 发布 log 与交付

更新 `docs/releases/<日期>-<主题>.md`，写明变化、实际部署/未部署状态、PR、前端/API/迁移身份、验收结果和限制，分别链接 baseline、candidate、production 的安全相对路径及覆盖计数。同步 `CHANGELOG.md` 和 `docs/releases/README.md` 索引；没有证据的部署/验收不能补造。

发布前后身份相符才可把 production 图与该版本关联。业务验收和用户既有部署授权按项目约定执行；快照完成不授予新部署权限。文档提交不会成为新运行版本。

交付时给出可点击的 `index.html`、覆盖数和发布日志，明确未拍、历史缺口和合成/实际生产的区别。新建 skill 的安装位置为 `~/.codex/skills/release-ui-snapshots/`；PDD404 可维护源为 `docs/skills/release-ui-snapshots/`，更新后同步安装副本。
