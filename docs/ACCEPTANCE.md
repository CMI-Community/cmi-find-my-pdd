| 场景 | 通过标准 |
|---|---|
| 首屏与模式 | 默认“我丢件了”；“我错收件了”切换清楚；完整国内单号的含义、查询与登记分开说明 |
| 首页统计 | 累计正式挂失/错收登记按单号和侧去重；成功匹配按包裹只计一次，不等于交还；网络错误不显示假零 |
| 队列备注 | 选填500字，两模式切换/刷新不丢失；批次安全重试；成功保存到数据库和本机回执；相同完整单号匹配显示对方备注，重复不覆盖原备注 |
| 建议与反馈 | 弹窗填写内容与可选联系方式，服务端确认后才成功；失败保留内容和请求键；手机提交按钮始终可见；仅管理员读取和审核，状态修改有审计 |
| 输入与校验 | 手填/粘贴、空格、大写转换、前导零正确；拒绝部分号码、特殊符号、全角和超长值；不推测缺位 |
| 扫码 | 点击即申请摄像头；允许后扫码，成功停止摄像头并填号；不自动查询；拒绝权限/无摄像头可直接手填 |
| 摄像头退出 | 关闭、成功、切后台、权限迟到或解码加载迟到都停止轨道，不在退出后重启 |
| 双向匹配 | 先丢件后误收、先误收后丢件均按完整同号显示对方自填联系；有对侧时优先匹配，同侧重复不遮挡 |
| 联系用途 | 表单告知相同单号另一方可查看；弹窗可复制，需核实归属；无管理员批准或站外通知依赖 |
| 未匹配列表 | 当前模式下叠加本机待提交单号，可删除/去重；明确“尚未正式登记”，失败不冒充已记录/查无此件 |
| 批量登记 | 一次联系方式提交 1–50 个单号；逐条显示登记/匹配/重复/已交还；感谢、截图、本机回执和下一步清楚 |

| 断网与刷新 | queryId、批量 requestId、凭证及原请求持久保存；重试不重复日志/登记；回执可从本机记录继续查看 |
| 双模式队列 | 模式切换保留各自待提交项和可恢复请求，不串单号、联系或回执 |
| 社区入口 | 真实公众号/群码/小助手可用；无配置显示服务状态；公益说明不声称“不保存个人信息” |

## 数据、权限与管理

| 场景 | 通过标准 |
|---|---|
| 单号唯一 | 一个规范国内单号仅一个主记录；每侧最多一条有效登记；并发同侧一成功一重复，对侧能关联同一主记录 |
| 查询日志 | 每次明确查询记录服务端具体时间、模式、来源、结果；网络重试只记一次；未登记查询也可在后台查看 |
| 专用联系例外 | 仅完整国内单号的有效对侧匹配返回 `{kind,value}`；已交还/撤回/已知承运商冲突不返回联系人 |
| 公开卡 | 公开编号、尾号、状态、时间与安全分享链接；无完整号码、联系方式、原图、地址或管理凭证 |
| 参数与投影 | 公开编号、尾号、额外 query flag、DB 多余字段不能扩大公开 DTO；失败不泄露 SQL 行或私人内容 |
| 本人管理 | cap 对应当前登记；其他人的 cap/空值/错误格式拒绝；key 仅 fragment/header，分享为公开链接 |
| 联系与撤回 | revision 冲突拒绝覆盖；撤回后旧查询重放不显示旧联系；claim/resolved 后本人不能撤回 |
| 管理员权限 | Supabase Auth 实际登录及 UUID 白名单；普通 authenticated 无管理员权；名单外或假 JWT 拒绝 |
| 归属与实际交还 | verify/claim/return/withdraw 分别审计；仅 return 增加一次交还；站外核实可基于真实误收登记完成，不伪造失主记录 |
| RLS 与 RPC | 六张 pdd 表及所有 pdd RPC 对 anon/普通 authenticated 拒绝；service-role 不进入前端 |
| 联系变更与幂等 | 重放读取当前投影，不缓存旧对方联系方式；更换请求体或 cap 用相同幂等键返回冲突 |
| 清理 | 查询/幂等元数据 30 天；结案/撤回 30 天清除联系、凭证、备注；匿名交还事实保留 |
| 清理并发屏障 | 管理请求先认证后等锁，清理撤销 cap 再放锁；旧请求必须失败，不能恢复联系人 |
| OCR 暂停 | OCR_ENABLED=false；旧业务写入口和候选匹配 GET 暂停，历史读取无匹配副作用；worker 经内部鉴权只清理旧资料，不租用任务或调用上游；单号清理独立运行 |

## 本轮已有证据与限制（2026-10-06 曼谷）

本地真实 PostgreSQL 验证器 `scripts/verify-postgres.mjs` 已运行通过：旧事务回归、并发同侧/对侧登记、查询后提交再核对、双向联系人、匿名/Auth 权限拒绝、30 天日志清理、站外核实的单侧实际交还及幂等计数。新双会话屏障实际观察管理请求等待 advisory lock，清理撤销凭证后释放锁，旧修改被 `FORBIDDEN` 拒绝，联系保持 null、cap 摘要为空、版本递增。

同一次验证实际执行数据库 pg_dump、AES-GCM 加密/解密、独立数据库 pg_restore 和恢复后的权限复核，结束后销毁临时数据库。仅使用虚构资料，不连接生产。这证明数据库迁移/事务/恢复，不证明云端对象存储、Auth/JWT、每日备份或域名已验收。

迁移前云端范围限定备份覆盖 14 张 public 业务表和 3 个存储 bucket，已加密并完成隔离恢复检查；Auth 仅有部分元数据。完整原生 public/Auth 备份等待私有数据库连接配置，尚不能把范围限定恢复写成完整灾难恢复通过。归档与实际检查明细由发布记录保存。

共享规则、PGlite 事务、Edge API 投影、前端队列和摄像头生命周期都有合成数据测试；最终 npm check/build 的次数与 SHA 由发布记录填写。桌面浏览器的移动视口、合成条形码和模拟 API 仅证明相应前端行为，不代替真实 iPhone、微信相机及真实云端接口。
